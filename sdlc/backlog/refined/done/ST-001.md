# ST-001: Budget planner for categories

**Source:** [`unrefined/ST-001.md`](../unrefined/ST-001.md) — raised by Johannes Widera
**Status:** refined

**As a** user of Finanzuhu
**I want to** see my monthly spending per category against a planned budget,
**so that** I notice while the month is still running whether I am overspending.

## Business context

The dashboard already breaks the range down by category (`byCategory` in
`src/lib/finance.ts`, rendered by `src/features/dashboard/category-list.tsx`).
That list answers "where did the money go" but not "is that a lot". A budget per
category turns the existing share view into a plan/actual comparison.

Budgets are reference data like `data/account.json`: they are maintained in the
repository, not edited in the app. The ledger is a fixed simulation — "current
month" therefore means the month of `asOf` (the date of the last booking), not
the wall clock.

## Scope decisions taken during refinement

- The comparison is shown **in the existing dashboard category list**, not on a
  separate page.
- Budgets live in **`data/budgets.json`**, served through the existing read-only
  path `data/` → API route → feature → UI. No writing API, no editing UI.

## Acceptance criteria

1. `data/budgets.json` holds one monthly amount per category, as positive euro
   values, for a subset of the existing expense categories.
2. A pure function in `src/lib/finance.ts` takes the transactions, the budgets
   and a reference date and returns, per category: budgeted amount, actual
   expenses of the reference month, and the ratio actual/budget.
3. The function counts only expenses (`amount < 0`) and only bookings whose date
   falls in the calendar month of the reference date.
4. Categories with a budget but no bookings in the month appear with an actual
   of 0.
5. Categories with bookings but **no** budget still appear in the list, without
   a budget bar — the current view loses nothing.
6. The dashboard category list shows, per budgeted category, the actual amount,
   the budgeted amount and a progress bar.
7. The bar is visually distinct in three states: within budget (< 80 %), close to
   the budget (80–100 %), over budget (> 100 %). The over-budget state is also
   readable without colour (e.g. text or icon), so it survives colour-blindness
   and the existing dark mode.
8. Ratios above 100 % cap the bar at full width; the numeric value still shows
   the real overspend.
9. A budget of 0 or a missing `budgets.json` does not break the dashboard: the
   view falls back to today's behaviour.
10. Unit tests in `tests/unit/` cover the new function: normal case, category
    without bookings, category without budget, overspend, month boundary.

## Not part of this story

- Creating or editing budgets in the UI (no writing API route)
- Budgets that differ per month, or budget history across months
- A total budget across all categories
- Budgets on income categories
- Notifications, emails or push when a budget is exceeded
- Carrying an unused budget over into the next month
- A separate `/budget` route

## Dependencies

- None blocking. Reads the existing `data/transactions.csv` and the existing
  dashboard feature.

## Open questions

- The dashboard has range tabs (week / month / 3m), the budget is monthly.
  **Assumption for implementation:** the budget bars always refer to the calendar
  month of `asOf` and are shown on the "month" tab only; the other tabs keep
  today's list. To be confirmed.
- Which categories get a budget in the seed file, and with which amounts?
- Which threshold counts as "close to the budget" — 80 % assumed above.
- What happens when a category is renamed in the CSV? Assumption: the budget
  entry simply no longer matches and the category shows as unbudgeted.
